# Prediction Persistence Design

## 1. Purpose

The prediction persistence component stores generated prediction
results in the project's SQLite database.

This allows prediction history to be retained for later analysis,
dashboard visualization, reporting, and evaluation.

3. Database Table

The prediction results are stored in the prediction_events table.

Field	Type	Description
id	INTEGER	Unique prediction event ID
timestamp	TEXT	Time associated with the prediction
metric	TEXT	Metric being predicted
current_value	REAL	Current observed value
predicted_value	REAL	Estimated next value
threshold	REAL	Configured warning threshold
risk_level	TEXT	Low, medium, or high
message	TEXT	Human-readable prediction message
created_at	TEXT	Time the prediction was stored
4. Repository Responsibility

The PredictionRepository provides the persistence interface
between the prediction layer and SQLite.

Its main responsibilities are:

Save prediction results.
Retrieve stored prediction results.
Convert database rows back into PredictionResult objects.
Keep database operations separate from prediction logic.

This separation improves modularity and maintainability.

5. Save Operation

When a prediction is generated, the repository stores:

Prediction timestamp
Metric name
Current value
Predicted value
Threshold
Risk level
Prediction message
Persistence timestamp

The prediction layer does not directly execute SQL queries.

6. Retrieval Operation

The repository retrieves prediction records ordered by timestamp.

Database records are converted back into PredictionResult
objects so that the rest of the application can work with the
same domain model used by the prediction component.

7. Testing

Prediction persistence is tested using a temporary SQLite database.

The test verifies that:

A prediction can be created.
The prediction can be saved.
The saved prediction can be retrieved.
Important prediction fields remain unchanged.

support:

11. Future Enhancement

The current persistence layer stores predictions generated by the
initial explainable trend-based predictor.

Future versions can additionally store:

Prediction confidence
Actual value after prediction
Prediction error
Model version
ML model metadata

This will allow quantitative evaluation of future prediction
models.
